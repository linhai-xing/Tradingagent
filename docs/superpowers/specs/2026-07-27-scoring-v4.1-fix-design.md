# Trist Selector v4.1 Scoring Fix — Design Spec

**Date:** 2026-07-27
**Status:** Approved
**Scope:** `TradingAgents/skills/trist_selector/scoring.py`, `screener.py`

## Problem

The scoring display shows "x/100" but the underlying math derives from a mis-match between rules.json (already v4.1, PA 70 + Bonus 20 + External 10 = 100) and scoring.py (still carrying v4.0 comments and hardcoded intermediate sub-scores calibrated for a 90-point PA scale).

## Solution

Align scoring.py to rules.json v4.1 by fixing comments, recalibrating intermediate sub-scores, and clarifying output formatting. No rules.json changes needed.

## Risk Assessment

- **Low risk**: All functions already cap via `min(score, cfg["weight"])`. The recalibration only affects score distribution within each dimension, not the overall total.
- **Backward compatible**: Existing scores will shift slightly due to recalibrated sub-scores but overall rankings should remain similar.
- **Test strategy**: Run `screener.py 600206`, `600667`, `603823`, `002396` before and after, compare PA sub-scores — they should sum to <= 70 and total should sum to <= 100.
